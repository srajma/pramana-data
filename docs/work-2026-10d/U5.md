# U5: readers' contributions — machine translation and OCR on request, scans, proposals, limits

The user (2026-10-16) asked for: machine translation on demand that **persists** (not a one-off answer) on verse,
chapter and document pages; icon buttons on every verse (translate, edit, history, share) and on whole pages
(translate everything, share); OCR on demand with a better model than the bulk one — "the cheapest model that would
OCR at nearly your standard"; the scans/PDFs behind documents, OCR'd or not; proposing metadata, parallels and new
content (text for redlinks and unread scans); all of it by API, documented; per-user and global spending limits;
OCR and translation only for signed-in readers.

Done by the integrator itself (the sub-task could not get a machine). Guide for readers and agents:
[docs/contributing.md](../contributing.md); metadata (M1): [docs/metadata.md](../metadata.md).

## What readers see

* **Every passage** (verse pages, chapter pages, whole short texts, every "load more" page) has a row of icons:
  **translate** (only where the passage has no English translation), **edit**, **history**, **share** (the system
  share sheet on phones; else the link is copied). Faint until the passage is hovered, always shown on touch screens.
  The old "translate" text button and "copy link" are gone.
* **Every reading page** has **translate** (everything shown that has no English yet, with progress `12/40`) and
  **share** beside the Linked menu.
* Requested translations appear **beside the text for every reader**, as *English (machine translation)* with the
  **MT** flag (tooltip: who asked, model, date); by default where the passage has no other English translation,
  and in the Linked menu like any translation.
* Visitors who are not signed in get a sign-in link instead of the translate button.
* A **Scans** tab on documents with known printed editions (`catalog/scans.yaml`: OCR'd ones and found but not
  yet read): the scan opens in an embedded viewer (archive.org), with its files and page; signed-in readers can
  **read pages** with the better OCR model and, on a document without text, **use the reading as its text**.
* A document **without text** offers **add the text** (paste or type: `#` headings, blank lines between passages;
  reviewed unless the reader is trusted).
* **Admin**: switches for translation and OCR requests, the limits (reader per day / month, ×trusted, site per
  day / month, USD), spending in the last 31 days and by reader.

Screenshots: Taishō 1353 with requested translations; Gītā 2 with the passage icons (in the session's browser).

## Design

* `pramana/contrib.py`: tables in `data/user.db` — `mt_seg (work, loc, lang, src hash, engine, text, job, actor)`,
  `ocr_page (item, page, engine, text, cost)`, `contrib_job`, `spend`. A translation is shown only while the
  passage's text hashes to what was translated (a corrected source hides it until asked again).
* Translation in context with `pramana/translate.py` (work title, place, author, date, summary, running glossary,
  the passage before) — Gemini 3.8 Flash; Claude Opus 5.5 for Classical Chinese, Tibetan, Greek, Latin, Arabic works
  of the foreign roots (`translate.FOREIGN_ENGINE`), as the 2026-10 MT bake-offs decided. ≤ 40 passages in the
  request, more as a background job (2 per API process; state in user.db; a restart marks running jobs
  `interrupted`).
* Live: `contrib.overlay` adds the requested translations to a page's `aligned` items as the virtual linked document
  `<content doc>~en-mt-r` (so the Linked menu, defaults and "+n" work unchanged; `linked.catalogue` flags it MT).
* Limits checked before every request with an estimate (`402` when over: estimate, left, limits); the real cost
  (OpenRouter `usage.cost`) recorded per call; a job stops when a limit is reached. Defaults: reader $0.50/day,
  $5/month (×10 trusted), site $10/day, $100/month (`edits.store.DEFAULTS`, admin settings).
* Content edits: kind `content` (`edits/model.py`; `content|<path>` targets, ≤ 2M characters, signed-in only;
  `content_segments` turns the text into passages), shown live by `edits/overlay.py` and inserted as the document's
  passages by the build (`edits/apply.py`).
* `/api/mt` (the old one-off endpoint, which could spend money anonymously) now needs an account.

## OCR model for requests: a fresh bake-off (2026-10-16)

The same pages as the 2026-10-06 bake-offs (`scripts/ocr_bakeoff.py`: 50 pages of modern prints from 9 Vedic Reserve
scans with clean editions; `scripts/ocr_bakeoff_old.py`: 41 pages of 19th-c. prints, lithographs and pages with
commentary from archive.org, tagged prompt), with the models released since. Excess error = the engine's
character error minus the best engine's on the same page. Spend $9.13.

| engine | modern prints: excess (mean / median) | old prints & commentary: excess (mean / median), gross failures | $ / 1,000 pages |
|---|---|---|---|
| Claude Opus 5.5 (reference) | 0.5% / 0.1% | 0.4% / 0.0%, 0 of 41 | 50–56 |
| **Gemini 4 Argon** | **1.4% / 0.7%** | **0.7% / 0.4%, 0 of 41** | **11–13** |
| Gemini 3.1 Pro | 1.2% / 0.8% | 2.8% / 0.5%, 1 | 12–15 |
| Claude Haiku 5.5 | 2.1% / 1.7% | 30.5% / 2.4%, 11 (mixes commentary into the text) | 1.6–1.8 |
| GPT-6.1 Sol | 3.1% / 2.5% | 3.9% / 0.3%, 2 | 35–42 (62 s a page) |
| Gemini 3.8 Flash (bulk) | 3.5% / 1.3% | 2.0% / 1.0%, 0 | 3.9–4.7 |
| GPT-6 Luna Pro | 12.7% / 10.3% | 37.5% / 15.9%, 16 | 5.7–6.8 |
| Mistral Large 4 | — (calls hung; dropped) | — | — |
| Datalab Indra (1M-parameter CPU model, added at the user's suggestion) | 25.7% / 21.4% | 249% / 223% (reads commentary and notes into the text; garbles conjuncts and accents) | 0 (CPU, ~0.2 s a page) |

**Chosen: Gemini 4 Argon** (`contrib.OCR_ENGINE`, admin setting `contrib_ocr_engine`): within about a point of Opus
on modern prints and 0.3 points on the hard pages (the only engine besides Opus with no gross failure there), at a
fifth of Opus's price. Gemini 3.1 Pro is as good on clean modern prints but three times worse than Argon on old
prints and commentary pages. Side finding: **Claude Haiku 5.5** reads clean modern prints better than Flash at
under half its price ($1.82) — a candidate for bulk OCR of modern editions (not for commentary pages).
Indra (Datalab, 2026-10) is free and fast but misreads a quarter of the letters of a Sanskrit print (sample, Maitrāyaṇī Saṃhitā p. 58: "इ्ाद, गाु्रं ्ार्िर्गायरत्रछन्दाः" for "कुर्याद्, गायत्रो ह्यग्निर्गायत्रच्छन्दाः"): not usable for Indic texts, even as a first pass.
Reports: [ocr-bakeoff.md](../ocr-bakeoff.md), [ocr-old-prints.md](../ocr-old-prints.md).

## Checks

* `tests/test_contrib_u5.py`: sign-in and limits refuse before any call; a translation is stored, recorded and not
  paid twice; shown beside the text, hidden when the source changes; OCR text without tags; a reader's text for a
  document without one is reviewed, shown live after approval and built into passages. `tests/test_edits.py`,
  `test_premade_mt.py`, `test_linking.py` pass.
* On the deployed library (local API): three Taishō 1353 passages translated in 4 s for $0.0022 and shown by default
  to every reader; one page of the 1952 Viśvalocanakośa read on request in 12 s for $0.0096 (Gemini 3.1 Pro, before
  the switch).

## For the integrator / the user

* **Production key**: on-demand translation and OCR need an OpenRouter key on the server. Add the repository
  secret **`OPENROUTER_API_KEY`** (GitHub → Settings → Secrets and variables → Actions); the deploy workflow writes
  it into the server's `.env.production` (other lines kept). Without it, requests answer 503.
* `pip install -e .` and the web build (new components; `marked`, `dompurify` for M1's analysis pages).
* Requested translations live in production's `data/user.db`; `contrib.export_mt()` gives them as records, should a
  later build want to fold them into `~en-mt` documents.
